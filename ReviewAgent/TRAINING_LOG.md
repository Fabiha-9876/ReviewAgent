# RoBERTa Classifier Training Log

## Training Run 1: Auto-Labeled Data (Completed)

**Date:** March 29, 2026
**Duration:** ~50 minutes on MPS (Apple Silicon)

### Data Used
- **Synthetic:** 500 reviews (pre-labeled, generated by template script)
- **MAALEJ:** 5,000 reviews (auto-labeled using keyword heuristics — NOT human labels)
- **RRGen:** 4,029 reviews (auto-labeled using keyword heuristics)
- **Total:** 9,529 reviews (7,623 train / 1,906 val)

### How Auto-Labeling Worked
The MAALEJ and RRGen datasets don't have category labels (only ratings), so a keyword heuristic approach was used. For example, reviews containing "crash", "broken", "error" were labeled as bug_report; reviews with "wish", "please add" were labeled as feature_request; reviews with "slow", "battery drain" were labeled as performance. If no keywords matched, low ratings (1-2) defaulted to bug_report, high ratings (4-5) to praise.

### Results
- Training Loss: 0.2046
- F1 (micro): 0.8355
- F1 (macro): 0.7478
- Precision: 0.8661
- Recall: 0.8069

### Limitation
Auto-labeling via keywords is approximate and noisy. The classifier learned keyword patterns rather than true semantic understanding of review categories.

## Training Run 2: Actual MAALEJ Human Labels (Completed — Current Model)

**Date:** March 29-30, 2026
**Duration:** ~30 minutes on MPS (Apple Silicon)

### Data Used
- **MAALEJ labeled (app_reviews.csv):** 5,008 reviews with real human annotations from Maalej et al. (2016) paper. Downloaded from github.com/mohammadzaeem/classification_of_app_reviews. This is the combined dataset from Maalej et al. (3,691 reviews) + Pan et al. (1,390 reviews).
- **Synthetic:** 500 reviews (generated by template script)
- **Total:** 5,508 reviews (4,406 train / 1,102 val, 80/20 stratified split)

### Original MAALEJ Labels Mapping
- "Problem Discovery" → bug_report (864 reviews)
- "Feature Request" → feature_request (444 reviews)
- "User Experience" → usability (607 reviews)
- "Rating" → praise (2,389 reviews)
- "Information Giving" → other (603 reviews)
- "Information Seeking" → other (101 reviews)

### Why RRGen and GUZMAN Were NOT Used for Classifier Training
- **RRGen (310K reviews):** Has review text + developer responses + star ratings, but NO category labels (not annotated as bug/feature/usability). It cannot be used for supervised classifier training. Its purpose in the pipeline is as a RAG corpus for Stage 4b (response generation).
- **GUZMAN (2K sentences):** Has aspect-sentiment annotations (e.g., "battery: negative") but NO category labels. Its purpose is for the aspect-based sentiment analysis component in Stage 1 and Knowledge Graph edges in Stage 2.

### Why Synthetic Data Was Included
The MAALEJ dataset only covers 4 categories: Problem Discovery (bug), Feature Request, User Experience, and Rating. It completely lacks two categories our pipeline needs: performance complaints (like "app is slow", "battery drain") and compatibility issues (like "doesn't work on my Samsung"). The 500 synthetic reviews provide 70 performance and 50 compatibility examples to fill those gaps. Without them, the classifier would have zero training examples for those labels.

### How Synthetic Data Was Generated
A template-based Python script (scripts/download_datasets.py) generates reviews by filling in pre-written sentence patterns with random real-world values. For example, a bug template like "App crashes when I {action} on my {device}" gets filled with "login" and "Samsung Galaxy S24". Each review gets a category label and a realistic star rating. The language is more predictable than real reviews, which is a limitation — ideally these would be replaced with real labeled data.

### Results
- Training Loss: 0.1877
- F1 (micro): 0.7671
- F1 (macro): **0.7992** (improved from 0.7478 with auto-labels)
- Precision: 0.7915
- Recall: 0.7441

### Per-Label F1 Scores
- bug_report: 0.816 (support: 202)
- feature_request: 0.627 (support: 107)
- performance: 1.000 (support: 14 — small, from synthetic only)
- usability: 0.552 (support: 138)
- compatibility: 1.000 (support: 10 — small, from synthetic only)
- praise: 0.820 (support: 490)
- other: 0.780 (support: 141)

### Sample Predictions (All Correct)
- "App crashes every time I try to login" → bug_report (0.966)
- "Please add dark mode to the app" → feature_request (0.919)
- "Battery drain is terrible with this app" → performance (0.629, flagged for HITL)
- "Love this app! Best photo editor ever!" → praise (0.818)
- "The checkout page is so confusing" → usability (0.832)
- "Not working on my Samsung Galaxy S24 with Android 15" → compatibility (0.753)

### Key Improvement Over Run 1
F1 macro improved from 0.7478 to 0.7992 (+6.9%) because real human annotations provide cleaner, more consistent training signal compared to noisy keyword heuristics. The model is now better balanced across all labels.

## Possible Next Steps for Further Improvement
1. **Semi-supervised self-training:** Use the trained classifier to label high-confidence (>0.9) RRGen reviews, add them to training set, retrain
2. **LLM-based labeling:** Use GPT-4 to label a subset of RRGen reviews for higher quality labels (costs API money)
3. **Multi-task learning:** Train jointly on MAALEJ (classification) + GUZMAN (aspect-sentiment) with shared RoBERTa backbone
4. **Get more real labeled data for performance/compatibility:** Have experts annotate RRGen reviews that mention performance and compatibility issues to replace synthetic data
